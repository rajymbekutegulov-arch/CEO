# Деплой на Render

## Что было исправлено

В проекте **все 89 относительных импортов уже имеют явное расширение `.js`**. Это проверяется командой:

```bash
npm run check:imports
```

Проверка контролирует три вещи:

1. у каждого относительного импорта есть `.js`;
2. файл действительно существует;
3. регистр пути совпадает с именем файла (Linux это важно).

Та же проверка запускается автоматически перед `npm start` через `prestart`. Если в деплой попадёт неполный набор файлов, вы увидите точный путь, а не общее `ERR_MODULE_NOT_FOUND`.

Дополнительно исправлено:

- сервер теперь слушает `0.0.0.0` — без этого Render не может подключиться к приложению;
- добавлен `render.yaml` с корректными командами;
- добавлена health-check точка `/api/health`.

## Настройки сервиса Render

| Параметр | Значение |
| --- | --- |
| Runtime | Node |
| Root Directory | **пусто** (корень репозитория, где лежит `package.json`) |
| Build Command | `npm install` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |
| Node.js | 20+ |

Переменные окружения:

| Ключ | Значение |
| --- | --- |
| `HOST` | `0.0.0.0` |
| `PORT` | Render задаёт сам, вручную не нужно |

Важно: создавайте именно **Web Service**, а не **Static Site**. Static Site не запускает Node-сервер, поэтому вход, прогресс и панель учителя работать не будут.

`render.yaml` уже содержит эти настройки. Если сервис создаётся заново, выберите **New → Blueprint** и подключите репозиторий. Если сервис уже существует, Render не применит `render.yaml` автоматически — проверьте настройки вручную.

## Порядок действий

1. Убедитесь, что в GitHub загружены **все** папки: `server/`, `server/seed/`, `public/`, `scripts/`, а также `package.json`, `render.yaml`.
2. В Render откройте сервис → **Settings** и проверьте Root Directory/Start Command.
3. Нажмите **Manual Deploy → Clear build cache & deploy**.
4. В логах должно появиться:

```
> ent-school8@1.0.0 prestart
> node scripts/check-imports.js
Проверка импортов: файлов 31, относительных импортов 89
✓ Все относительные импорты корректны...
```

5. После `Server listening` откройте `/api/health` — должен вернуться `{"ok":true,...}`.

## Если ERR_MODULE_NOT_FOUND повторится

Пришлите полную строку ошибки — в ней указан конкретный отсутствующий файл. Типичные причины:

- **не загружена папка `server/seed`** — тогда отсутствует `server/seed/index.js`;
- **Root Directory указан как `server`**, а Start Command остался `node server/index.js` — путь превращается в `server/server/index.js`;
- сервис подключён к другому репозиторию/старой ветке или задеплоен старый коммит;
- остался старый build cache — помогает **Clear build cache & deploy**.

Локальная проверка на чистой копии репозитория:

```bash
npm ci
npm run check
npm start
```

Затем:

```bash
curl http://localhost:4173/api/health
```

## Данные на Render

`data/db.json` создаётся автоматически. На бесплатном плане файловая система Render **эфемерная**: аккаунты, результаты и правки учителя сохраняются между запросами, но могут исчезнуть после redeploy/restart.

Для постоянного хранения:

- подключить Render Disk и указать `DATA_DIR=/var/data` (на платном плане), либо
- перейти на PostgreSQL/SQLite с внешним хранилищем.

Переменная `DATA_DIR` уже поддерживается сервером.

## Безопасность после публикации

Для публичного доступа желательно добавить:

- HTTPS (Render даёт его автоматически);
- флаг `Secure` у cookie;
- восстановление пароля и подтверждение почты;
- резервное копирование `data/db.json`;
- журналирование действий учителя.
